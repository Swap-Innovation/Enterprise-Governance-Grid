# Cross-pack completeness — Data Products ↔ Catalogs ↔ Semantics

Last reviewed: 2026-08-12

## Goal

Every **marketplace Data Product** (global + DE/AT/HR/HU/PL) must have a connected knowledge graph spanning:

| Pack | Required asset types |
| --- | --- |
| **Data Products** | Data Product · Output Port · Input Port (global) · Data Contract · Contract Field (all columns) |
| **Technical Catalog** | System · Database · Schema · Table · Column (all fields) |
| **Business Catalog** | Data Domain · Data Model · Data Entity · Data Attribute (all fields) · Business Term |
| **Semantic Control Plane** | Namespace · entity Concept · property Concepts · Federation Edge (NATCO→global) · Mapping Record |

And the converse: every technical Table/Column used by a product **represents** Concepts, is **implemented by** Entity/Attribute, and is **governed** via Contract Fields.

## Gaps found (pre-fix) and remediation

| Gap | Before | Fix |
| --- | --- | --- |
| Non-C360 families had **no DataEntity / DataAttribute / DataModel** | Only Customer 360 logical model | `e2e-cross-pack-complete.cypher` creates per-family Model→Entity→Attributes |
| NATCO tables for non-C360 had **only 1 column / 1 contract field** | Incomplete vs global | Expand all global columns onto each NATCO table + contract |
| Property Concepts missing for marketplace columns | Entity Concept only | Create `shared_property` Concepts + NATCO federation |
| Entity↔Table / Attribute↔Column bridges missing | Partial | `IMPLEMENTED_IN` / `IMPLEMENTS_ENTITY` / Attribute→Column |
| Orphan `asset-*` contract duplicates | Unlinked products/tables | Detached in completeness script; prefer e2e ids (`dp-*`) |
| Q3 demo under-showed biz/tech grain | Domain path only | Q3 unions for Entity/Attribute `MAPS_TO`, Entity `IMPLEMENTED_IN` Table, Attribute `IMPLEMENTED_IN` Column |

## Verification checklist

For each `dp-{family}` and `dp-{family}-{de|at|hr|hu|pl}`:

1. Has Output Port → Data Contract → **N** Contract Fields (N = column count)
2. Output Port → Table → **N** Columns, each `REPRESENTS` a Concept
3. Belongs to Data Domain → owns Model → Entity → **N** Attributes
4. Entity `MAPS_TO` entity Concept; Attributes `MAPS_TO` property Concepts
5. Entity `IMPLEMENTED_IN` Table; Attributes `IMPLEMENTED_IN` Columns
6. Business Term `MAPS_TO` entity Concept
7. NATCO: local Concept `FEDERATES` global; local columns federate property Concepts
