# Semantic setup options — A vs C

Two **structurally unique** setups for Germany with B2B / B2C / Network business units under the NATCO.

| Option | Name | Unique idea |
| --- | --- | --- |
| **A** | [Centralized NATCO](A-single-germany-namespace.md) | One `opt-a-de` namespace · BUs co-steward · tools **`BINDS_TO`** Germany · **no tool namespaces** |
| **C** | [BU federated canonical](C-federated-canonical.md) | BU namespaces are **SoR** · tools **`MAPS_TO`** BU · **`FEDERATES`** to global · **recommended** |

**Not showcased:** [Option B (migration phase)](B-tool-namespaces.md) — retired because it duplicated C’s graph shape.

**Demo UI:** `/demo/customer360/options`  
**Machine scenarios:** [`contracts/examples/scenarios/semantic-options/`](../../contracts/examples/scenarios/semantic-options/)  
**Neo4j seed:** `backend/neo4j/cypher/e2e-semantic-options.cypher` (queries **O1 / O3**)

## Decision axis

```text
Centralize (A)  ←————————————————→  Federate by BU (C)

A: one Customer in Germany, all tools bind there
C: Geschäftskunde (B2B) + Kunde (B2C) in BU namespaces, tools map in
```

## How to present

1. Explain B2B / B2C / Network stewardship under Germany.
2. Show **A** — lock-down: one publish surface, smallest graph.
3. Show **C** — target: BU SoR + tool execution layers.
4. Close on **C**; mention B only as “migration narrative”, not a third tab.
