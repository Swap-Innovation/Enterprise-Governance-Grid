# Semantic setup options — client showcase

Three **parallel demo setups** for moving from tool-owned semantic layers (Power BI, Palantir, …) to a Semantic Control Plane. Same Germany / Customer story; different namespace strategy.

| Option | Name | Idea |
| --- | --- | --- |
| **A** | [Single Germany namespace](A-single-germany-namespace.md) | One `de` namespace; all tools share it |
| **B** | [Tool-specific namespaces](B-tool-namespaces.md) | Each tool keeps its own semantics |
| **C** | [Federated canonical](C-federated-canonical.md) | Canonical `global`/`de` + tool namespaces + mapping |

**Demo UI:** `/demo/customer360/options`  
**Machine scenarios:** [`contracts/examples/scenarios/semantic-options/`](../../contracts/examples/scenarios/semantic-options/)  
**Neo4j seed:** `backend/neo4j/cypher/e2e-semantic-options.cypher` (queries **O1 / O2 / O3**)

## How to present

1. Open **Options** in the demo nav — switch A → B → C live.
2. Show namespace tree + concept table for each.
3. Close with recommendation: **C as target**; A only if org is ready for lock-down; B as transitional bridge.

## What we did *not* do

We did **not** triplicate the whole Contracts + marketplace graph. Each option is a **focused Germany + Power BI + Palantir overlay** tagged `optionId`, so the main Customer 360 demo stays intact and clients can compare strategies without three full product copies.
