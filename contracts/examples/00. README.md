# Examples (master)

**Single home for demo / pitch / scenario JSON** used by the Contracts UI, docs, and KG narrative.

Do **not** put catalog asset instances here — those stay under each pack type (KG enrich SoR):

```text
contracts/{Pack}/{AssetType}/example.json
contracts/{Pack}/{AssetType}/examples/*.json   # extras
contracts/{Pack}/examples/index.json           # refs only
```

## Layout

```text
contracts/examples/
  00. README.md              ← this hub
  index.json                 ← machine catalog
  scenarios/                 ← cross-pack walkthroughs (KG / Completeness)
    end-to-end-customer-flow.json
    multi-natco-customer.json
  pitch/                     ← showcase UI + docs (Vite imports via @examples)
    customer-contracts.json
    customer-context-graph.json
    multi-natco-customer-assets.json
    technical-catalog-assets.json
    tmforum.json
    pitch-concepts.json
```

## Who consumes what

| Consumer | Path |
| --- | --- |
| Neo4j enrich | `{Pack}/{AssetType}/example.json` + `Type/examples/*` |
| KG / Completeness docs | `scenarios/*` |
| Frontend ContractBrowser · ConceptLibrary · Federation | `@examples/*` → `pitch/*` |
| Docs demos / guides | links into `contracts/examples/…` |

## Frontend import

`frontend/src/data/examples` is a **symlink** to this `pitch/` folder.

```ts
import tmforum from '../data/examples/tmforum.json'
```

Vite also resolves `@examples/*` → `contracts/examples/pitch` (optional).
